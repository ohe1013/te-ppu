# 하이브리드 판타지 픽셀 에셋 설계

- 작성일: 2026-08-02
- 상태: 사용자 승인 완료
- 적용 대상: `feat/pve-delivery`
- 목적: 현재 3층 도형 기반 PvE 프로토타입을 5층 캐릭터형 게임으로 확장하고, 사용자가 제작한 에셋을 게임 로직과 분리해 안전하게 교체할 수 있게 한다.

## 1. 목표와 범위

이 설계는 밝고 귀여운 판타지 캐릭터 일러스트와 레트로 픽셀아트 전투 요소를 결합한다. 캐릭터는 층 진입·결과 화면의 큰 일러스트와 대전 HUD의 작은 얼굴 초상화로 표시한다. 양쪽 `10×20` 게임판은 현재와 같은 크기를 유지하며 캐릭터 때문에 축소하지 않는다.

첫 에셋 패스에는 다음이 포함된다.

- 주인공, 태엽 부엉이, 1~4층 간부, 5층 마왕
- 탑 외부와 5개 층 배경
- 블록 7종, 방해 블록, 아이템 3종
- 공통 전투 픽셀 효과와 UI 아이콘
- 효과음 8종과 배경음 5종
- 3층 진행 구조를 5층으로 확장하는 데이터·저장·AI 변경

프레임 단위 캐릭터 애니메이션, 음성 연기, 컷신 영상, 가로 화면, 사용자 대전용 캐릭터 에셋은 이번 범위에 포함하지 않는다. 정적 표정 교체에 흔들림·확대·이동·페이드 같은 코드 애니메이션을 결합한다.

## 2. 시각 언어

### 2.1 캐릭터

- 둥글고 읽기 쉬운 실루엣, 깨끗한 선, 밝은 중간 명도를 사용한다.
- 캐릭터 얼굴과 몸은 부드러운 2D 일러스트로 그린다.
- 장갑, 렌치, 동력 코어, 갑옷 장식에는 제한적인 픽셀 무늬를 사용해 전투 화면과 연결한다.
- 1~4층 간부는 과장된 소품과 표정으로 허술함을 드러낸다.
- 5층 마왕은 코믹한 표정을 사용하지 않는다. 거대한 갑옷, 뿔, 무거운 망토와 검정·진홍·금색 팔레트로 위협을 유지한다.

### 2.2 전투 요소

- 블록, 방해 블록, 아이템 표식, 공격 효과는 16×16 논리 픽셀 격자에서 설계하고 64×64로 4배 내보낸다.
- 런타임에서는 `nearest-neighbor` 스케일링을 사용한다.
- 실제 모바일 보드 한 칸은 약 16~19.4 CSS px이므로 내부 문양은 두세 덩어리와 강한 명암 대비만 사용한다.
- 아이템 표식은 글자 없이 실루엣만으로 식별한다.
- 캐릭터·배경은 일반 선형 보간을 사용한다.

### 2.3 색 구성

- 주인공: 청록, 크림, 구리
- 태엽 부엉이: 크림, 황동, 청록 발광 코어
- 1층: 황토, 올리브, 상자·창고 색
- 2층: 보라, 산성 연두, 연금술 유리 색
- 3층: 파랑, 은색, 경비대 깃발 색
- 4층: 주황, 남색, 전선·동력로 색
- 5층: 검정, 진홍, 금색

블록 7종은 서로 다른 색과 명도 차이를 동시에 사용한다. 색만으로 구별하지 않도록 각 타일에 서로 다른 단순 픽셀 무늬를 넣는다.

## 3. 캐릭터와 층 구성

표시 이름은 향후 현지화 문자열로 관리한다. 다음 영문 ID는 파일과 코드에서 고정한다.

| ID | 역할 | 핵심 설정 |
| --- | --- | --- |
| `hero-engineer` | 플레이어 | 고장 난 탑을 고치러 온 명랑한 견습 마도공학자 |
| `owl-companion` | 구출 대상·마스코트 | 탑 동력장치의 열쇠가 되는 태엽 부엉이 파트너 |
| `quartermaster` | 1층 간부 | 훔친 물건을 어디에 뒀는지 잊어버리는 보급 담당 악당 |
| `alchemist` | 2층 간부 | 위험한 제조법을 자꾸 반대로 읽는 폭발광 연금술사 |
| `guard-captain` | 3층 간부 | 위엄은 있지만 방향 감각이 없는 경비대장 |
| `dark-engineer` | 4층 간부 | 실력은 있지만 레버와 배선을 거꾸로 설치하는 악의 기술자 |
| `demon-king` | 5층 마왕 | 거대한 갑옷과 뿔을 지닌 냉정하고 유능한 정통 마왕 |

난이도와 분위기는 층마다 강해진다. 웃음은 1~4층 간부의 행동과 마왕이 그 결과를 참는 반응에서 나오며, 마왕 자체는 무능하거나 우스운 인물로 만들지 않는다.

## 4. 원본과 런타임 파일 분리

편집 원본은 번들 밖에서 관리한다.

- 원본: Figma, AI, PSD 또는 CLIP 파일과 무손실 WAV
- 런타임: WebP, PNG, SVG, MP3와 스프라이트시트 JSON
- 원본 파일은 `public/`, `src/` 또는 `.ait` 입력 경로에 두지 않는다.
- 저장소에 원본을 보관해야 한다면 별도 `art-source/`와 Git LFS를 사용하고 빌드 입력에서 제외한다.

| 종류 | 수량 | 런타임 규격 | 비고 |
| --- | ---: | --- | --- |
| 앱 로고 | 1 | 600×600 PNG | 정사각형, 불투명 배경, 둥근 모서리 사전 적용 금지 |
| 캐릭터 큰 일러스트 | 7 | 1024×1024 투명 WebP | 인물 전체가 안전 영역 안에 들어가야 함 |
| HUD 얼굴 초상화 | 38 | 256×256 투명 WebP | 얼굴 중심, 동일한 눈 위치와 크롭 |
| 탑 외부 배경 | 1 | 840×1480 WebP | 층 선택 화면 공용 |
| 층별 배경 | 5 | 각 840×1480 WebP | 중앙 보드 영역은 저대비·저밀도 |
| 블록 타일 | 7 | 각 64×64 투명 PNG | 16×16 논리 픽셀의 4배 출력 |
| 방해 블록 | 1 | 64×64 투명 PNG | 일반 블록과 명확히 구별 |
| 아이템 표식 | 3 | 각 64×64 투명 PNG | 글자 없이 16px 축소에서도 식별 |

| 전투 효과 | 1 atlas | 최대 2048×2048 PNG + JSON | 투명 여백 트리밍, 프레임 이름 고정 |
| 효과음 | 8 | MP3 | 원본은 48kHz 24-bit WAV |
| 배경음 | 5 | MP3 | 원본은 48kHz 24-bit WAV |

초상화 38장의 구성은 다음과 같다.

- 주인공 6장: `idle`, `focus`, `attack`, `hit`, `win`, `loss`
- 1~4층 간부 각 6장, 총 24장: `idle`, `smug`, `attack`, `hit`, `panic`, `defeat`
- 마왕 5장: `idle`, `attack`, `hit`, `rage`, `defeat`
- 태엽 부엉이 3장: `idle`, `worry`, `cheer`

WebP는 알파 채널을 유지하고 캐릭터 품질 85 이상, 배경 품질 80 이상을 기준으로 내보낸다. 결과물에서 테두리 번짐이 보이면 해당 파일만 무손실 WebP로 전환한다.

## 6. 전투 효과와 이벤트 연결

스프라이트시트에는 다음 프레임 그룹을 포함한다.

- `move-dust`: 블록 이동 잔상
- `rotate-spark`: 회전 픽셀 불꽃
- `land-impact`: 착지 충격
- `line-clear`: 줄 삭제 섬광
- `attack-shot`: 상대 보드 방향으로 이동하는 공격 탄환
- `garbage-land`: 개별 방해 블록 착지 충격
- `item-acquire`: 아이템 획득 발광
- `freeze-overlay`: 시간 멈춤 빙결 테두리
- `combo-pop`: 콤보 숫자 강조

게임 이벤트는 다음 표현을 선택한다.

| 이벤트 | 초상화 | 픽셀 효과 | 사운드 |
| --- | --- | --- | --- |
| 이동 | 유지 | `move-dust` | `move` |
| 회전 | 주인공은 `focus`, 상대는 현재 표정 유지 | `rotate-spark` | `rotate` |
| 착지 | 유지 | `land-impact` | `land` |
| 줄 삭제 | `focus` | `line-clear` | `clear` |
| 공격 전송 | `attack` | `attack-shot` | `attack` |
| 방해 블록 피격 | `hit` | `garbage-land` | `land` |
| 아이템 획득 | 현재 표정 유지 | `item-acquire` | `item` |
| 시간 멈춤 사용 | 사용자는 `attack`, 대상은 `hit` | `freeze-overlay` | `item` |
| 승리 | 주인공은 `win`; 1~4층 상대 승리는 `smug`; 마왕 승리는 `idle` | 결과 화면 코드 연출 | `win` |
| 패배 | 주인공은 `loss`; 패배한 상대는 `defeat` | 결과 화면 코드 연출 | `loss` |

마왕 효과는 동일한 프레임 그룹을 느린 속도, 낮은 흔들림, 더 무거운 음색으로 사용한다. 코믹한 찌그러짐이나 과도한 바운스는 적용하지 않는다.

## 7. 사운드 규격

효과음 ID는 현재 `AudioPort`의 큐와 일치한다.

- `move`, `rotate`, `land`, `clear`, `attack`, `item`, `win`, `loss`
- 효과음 길이: 0.05~1초
- 효과음 원본: 48kHz 24-bit WAV, 모노 권장
- 런타임: MP3, 피크 -1dBFS 이하

배경음 ID는 다음과 같다.

- `tower`: 탑 선택과 층 진입
- `early-floors`: 1~2층
- `late-floors`: 3~4층
- `demon-king`: 5층
- `ending`: 구출과 엔딩

배경음은 60~90초 길이의 자연스러운 루프를 제공한다. 원본은 48kHz 24-bit WAV, 런타임은 160kbps 이상 MP3를 사용한다. 효과음과 음악의 재생 실패는 게임 진행에 영향을 주지 않는다.

## 8. 에셋 매니페스트와 로딩 흐름

코드는 파일명을 화면 곳곳에 직접 적지 않고 타입이 있는 에셋 매니페스트를 사용한다.

```text
BOOT
  -> 공통 번들 로드: 블록, 아이템, UI, 공통 효과
  -> 탑 화면 표시
층 선택
  -> 현재 층 번들 로드: 배경, 상대 큰 그림, 상대 초상화, 필요한 음악
  -> 층 진입 화면 표시
대전 시작
  -> 게임 코어와 독립적으로 표정·효과 이벤트 소비
  -> 다음 층 번들을 낮은 우선순위로 미리 로드
대전 종료
  -> 결과 표정과 큰 그림 표시
```

주인공과 공통 전투 에셋은 한 번만 캐시한다. 현재 층과 다음 층만 GPU에 유지하고, 이전 층의 큰 배경과 초상화는 결과 화면을 벗어난 뒤 해제할 수 있다. 에셋 준비 상태가 AI, 입력, 콤보, 공격 계산에 영향을 주면 안 된다.

## 9. 실패 대체와 복구

- 캐릭터 큰 그림 실패: 해당 캐릭터 팔레트의 단순 실루엣과 이름을 표시한다.
- 초상화 실패: 원형 색상 배지와 상태 텍스트를 표시한다.
- 배경 실패: 층 팔레트 기반 단색·그라데이션을 표시한다.
- 블록·아이템·효과 실패: 현재 PixiJS 도형 렌더링을 유지한다.
- 사운드 실패: 무음으로 계속 진행한다.
- 다음 층 미리 로드 실패: 층 진입 시 한 번 재시도하고, 실패하면 대체 표시로 시작한다.

하나의 선택적 에셋 실패가 앱 부팅이나 대전을 막아서는 안 된다. 필수 매니페스트 자체가 잘못된 경우 개발 빌드에서는 명확히 실패시키고, 배포 빌드에서는 도형 기반 안전 모드로 전환한다.

## 10. 5층 진행 구조 확장

현재 코드의 3층 고정 값을 데이터 기반 5층 구성으로 바꾼다.

- `Floor`와 라우팅은 1~5층을 지원한다.
- 탑 화면은 5개 층의 잠금·완료 상태를 표시한다.
- 5층 승리 후에만 태엽 부엉이 구출 엔딩으로 이동한다.
- 기존 저장 데이터는 그대로 읽고 4·5층 완료 값을 `false`로 보충한다.
- 기존 최고 해금 층은 유지하며 새 최대값은 5로 제한한다.
- 각 새 게임은 현재 층의 아이템 등장 기록, 인벤토리, 콤보, 공격 대기열을 초기화한다.

초기 AI 프로필은 다음과 같이 단조롭게 강화한다.

| 층 | 반응 틱 | 탐색 깊이 | 상위 후보 무작위 범위 |
| --- | ---: | ---: | ---: |
| 1 | 48 | 0 | 5 |
| 2 | 38 | 0 | 4 |
| 3 | 27 | 1 | 3 |
| 4 | 19 | 1 | 2 |
| 5 | 12 | 2 | 1 |

최종 수치는 자동 대전 시뮬레이션에서 승률이 층마다 단조롭게 낮아지고 무한 루프·무효 명령·메모리 증가가 없는지 검증한 후 조정한다. 조정하더라도 기존 3층 프로필의 최저·최고 난이도 반응 틱인 48과 12를 새 1층과 5층의 끝값으로 유지한다.

## 11. 성능과 용량 예산

- 런타임 에셋 총합 목표: 30MB 이하
- `.ait` 압축 해제 총합: 100MB 이하
- 스프라이트시트 한 장: 최대 2048×2048
- 큰 배경: 동시에 현재 층과 다음 층 두 장까지만 준비
- 장식 효과: 기존 최대 동시 개수 제한을 유지
- 보드: 360×640에서 각 160×320, 430×932에서 각 194×388 기준을 유지

에셋 추가 후에도 상대 보드를 축소하거나 숨기지 않는다. 캐릭터 초상화는 기존 HUD 안에 들어가고, 큰 일러스트는 대전 전후 화면에서만 사용한다.

## 12. 검증 기준

### 12.1 자동 검증

- 매니페스트의 모든 필수 ID와 파일이 존재한다.
- PNG·WebP 크기와 알파 조건이 규격과 일치한다.
- 픽셀 에셋의 렌더 스케일 모드가 `nearest`다.
- 선택적 에셋 실패 시 대체 렌더링으로 대전이 끝까지 진행된다.
- 1~5층 라우팅, 잠금 해제, 재도전과 5층 엔딩이 동작한다.
- 구버전 3층 저장 데이터가 손실 없이 5층 스키마로 읽힌다.
- 360×640과 430×932에서 양쪽 보드가 같은 크기이며 오버플로가 없다.
- 사운드 비활성화·백그라운드 전환 시 음악과 효과음이 중지된다.
- 전체 `.ait` 검사에서 100MB 제한과 기존 보안 게이트를 통과한다.

### 12.2 수동 검증

- 작은 HUD에서 모든 캐릭터의 기본·공격·피격 상태를 구별할 수 있다.
- 세 아이템 표식은 글자 없이도 구별된다.
- 블록 7종은 색각 차이가 있어도 무늬로 구별된다.
- 층별 배경이 보드, 고스트, 방해 블록, 공격 예고를 가리지 않는다.
- 1~4층은 코믹하지만 5층 마왕전은 시각·음악 모두 위협적으로 느껴진다.
- Android와 iOS 실기기에서 픽셀 가장자리가 흐려지지 않는다.

## 13. 아티스트 전달 체크리스트

각 전달 묶음에는 다음을 포함한다.

1. 레이어가 보존된 원본 파일
2. 이 문서의 파일명과 크기를 따르는 런타임 내보내기
3. 사용한 폰트·브러시·음원·텍스처의 제작자와 라이선스 기록
4. 미리보기 연락처 시트 또는 썸네일 시트
5. 알파 가장자리와 16px 축소 상태 확인본

공식 게임의 캐릭터, 로고, 고유 UI, 블록 표정, 공격 연출 또는 사운드를 복제하지 않는다. 모든 최종 에셋은 이 프로젝트만의 실루엣, 무늬, 팔레트와 명칭으로 제작한다.
