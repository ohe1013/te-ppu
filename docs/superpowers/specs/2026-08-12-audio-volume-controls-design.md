# 효과음 가청성 수정과 오디오 음량 조절 설계

작성일: 2026-08-12  
상태: 사용자 문서 승인 완료, 구현 계획 작성 중

## 1. 배경과 확인된 원인

게임 이벤트와 조작 입력은 `AudioPort.play()`까지 정상적으로 전달되고 효과음 파일도 자산 manifest에 포함되어 있다. 관련 오디오·UI 단위 테스트 46개도 현재 기준에서 통과한다.

문제는 효과음 샘플의 런타임 gain이다. 저작된 BGM과 효과음의 원본 RMS는 대체로 비슷하지만, BGM은 gain `1`로 재생되는 반면 효과음에는 intensity에 따라 `0.14~0.20`이 다시 곱해진다. 따라서 효과음은 BGM보다 약 14~17dB 낮아져 모바일 스피커에서 사실상 들리지 않거나 음악에 묻힌다.

이번 변경은 효과음 경로의 기준 음량을 다시 맞추고, 사용자가 BGM과 효과음을 각각 조절할 수 있게 한다.

## 2. 확정된 제품 결정

- 기존 `전체 소리` 토글과 진동 설정을 유지한다.
- `BGM 음량`과 `효과음 음량`을 별도 슬라이더로 제공한다.
- 슬라이더 범위는 `0~100%`, 표시와 조작 간격은 `10%`로 한다.
- 새 게임과 기존 저장 데이터의 기본값은 `BGM 70%`, `효과음 100%`로 한다.
- 슬라이더를 움직이는 동안 실제 음량을 즉시 반영한다.
- 효과음 슬라이더 조작을 마치면 짧은 회전 효과음을 한 번 재생해 현재 크기를 확인하게 한다.
- 설정은 진행 데이터에 저장하여 재접속 후에도 유지한다.
- 현재 효과음의 과도하게 낮은 기준 gain도 함께 교정한다.

## 3. 목표

1. 이동, 회전, 착지, 줄 제거, 공격, 아이템, 승패 효과음이 기본 설정에서 BGM에 묻히지 않게 한다.
2. BGM과 효과음의 크기를 서로 독립적으로 조절하게 한다.
3. 음량 변경을 조작 중 즉시 들을 수 있고, 조작 종료 후 영구 저장되게 한다.
4. 기존 음소거, 덕킹, 앱 suspend/resume, 지연 디코딩과 오디오 수명 주기를 유지한다.
5. 기존 schema 1~4 저장 데이터를 손실 없이 새 설정 형식으로 이전한다.

## 4. 비목표

- 기기 시스템 음량 조절
- 트랙별 또는 효과음 종류별 개별 음량
- 음향 이퀄라이저, 압축기, 공간 음향
- BGM 선택·업로드 기능
- 게임 규칙, 점수, AI, 랭킹 변경

## 5. 설정 모델과 저장 마이그레이션

진행 데이터 schema를 5로 올리고 설정을 다음 형태로 확장한다.

```ts
interface AudioSettings {
  soundEnabled: boolean;
  bgmVolume: number;
  sfxVolume: number;
}

interface ProgressSettings extends AudioSettings {
  hapticsEnabled: boolean;
}
```

- 저장값은 `0~100` 범위의 안전한 정수만 허용한다.
- UI는 `step=10`으로 조작하지만 파서는 범위 내 모든 정수를 받아 향후 조정 폭 변경과 호환되게 한다.
- schema 5는 설정 키를 정확히 검증하며 범위 밖 값, 실수, 문자열, 추가 키를 거부한다.
- schema 1~4의 `{ soundEnabled, hapticsEnabled }`는 기존 값을 보존하고 `bgmVolume: 70`, `sfxVolume: 100`을 추가해 schema 5로 이전한다.
- 현재 저장소의 백업 우선 복구와 마이그레이션 후 재저장 동작을 유지한다.
- `TowerController.updateSettings()`는 boolean 설정과 두 음량 정수를 모두 검증한 뒤 기존처럼 메모리에 먼저 적용하고 저장한다. 저장 실패 시 적용된 값은 유지하며 기존 재시도 흐름을 사용한다.

## 6. 오디오 그래프

사용자 음량과 음악 덕킹·페이드를 같은 gain 노드에서 처리하지 않는다. 서로 다른 책임을 가진 버스를 둔다.

```text
BGM source
  -> music dynamics gain (fade / duck)
  -> BGM volume gain (0.0~1.0)
  -> destination

SFX source
  -> cue gain (intensity / cue balance)
  -> SFX volume gain (0.0~1.0)
  -> destination
```

- `AudioPort`에 BGM·효과음 정규화 음량을 한 번에 적용하는 `setVolumes()` 경계를 추가한다.
- `AppRoot`는 불러온 진행 설정과 이후 변경을 `setEnabled()` 및 `setVolumes()`에 동기화한다.
- BGM volume gain은 사용자 값만 담당한다.
- 기존 music dynamics gain은 `1`을 기준으로 크로스페이드와 덕킹만 담당한다. 따라서 덕킹 복원이 사용자의 BGM 음량을 100%로 덮어쓰지 않는다.
- 각 효과음의 cue gain은 intensity와 회전음 변형을 담당하고, 모든 효과음은 공통 SFX volume gain으로 들어간다.
- gain 노드는 AudioContext가 처음 unlock될 때 지연 생성하며 destroy에서 해제한다.
- 컨텍스트 생성 전 변경된 음량도 내부 상태에 보관했다가 첫 생성 시 반영한다.

## 7. 효과음 기준 음량 교정

현재 샘플 gain `0.14~0.20`은 제거하고, 기본 `BGM 70% / 효과음 100%`에서 짧은 효과음의 체감 크기가 음악과 비슷하거나 약간 앞에 오도록 intensity 계층을 다시 정한다.

- intensity 0도 이동·회전·착지가 모바일 스피커에서 구분되어야 한다.
- intensity가 0에서 3으로 증가할 때 gain과 재생 속도는 계속 단조 증가한다.
- 가장 강한 단일 샘플은 자체적으로 클리핑하지 않아야 한다.
- 같은 프레임 cue 중복 제거와 강한 clear/attack의 덕킹은 유지한다.
- 디코딩 실패 시 오실레이터 대체음도 같은 SFX volume 버스를 거치고, 기본 설정에서 식별 가능한 크기로 교정한다.
- 원본 MP3를 다시 저작하지 않고 런타임 믹스만 수정한다.

정확한 계수는 테스트로 경계를 고정한 뒤 청음에서 미세 조정한다. 구조적 완료 조건은 효과음에 기존의 `0.14~0.20` 감쇠가 다시 적용되지 않는 것이다.

## 8. 설정 UI와 상호작용

기존 설정 모달 안의 첫 번째 체크박스 문구를 `효과음`에서 `전체 소리`로 바로잡고 아래 순서로 배치한다.

1. 전체 소리 토글
2. BGM 음량 슬라이더와 현재 퍼센트
3. 효과음 음량 슬라이더와 현재 퍼센트
4. 진동 토글

각 range input은 한국어 접근성 이름, 현재 값, `min=0`, `max=100`, `step=10`을 제공한다.

### 조작 중

- 컴포넌트는 두 슬라이더의 로컬 표시값을 가진다.
- 포인터 드래그나 키보드 조작의 각 값 변경 시 표시값과 실제 오디오 버스를 즉시 갱신한다.
- 이 미리보기 경로는 저장 완료를 기다리지 않으며 게임 입력을 차단하지 않는다.

### 조작 종료

- pointer up, keyboard key up, blur 또는 모달 닫기 시 마지막 값만 `onSettingsChange()`로 저장한다.
- 이미 저장한 값과 같으면 중복 저장하지 않는다.
- 효과음 값이 실제로 바뀐 조작을 마치면 새 gain을 적용한 후 `rotate` cue를 한 번 재생한다.
- 저장 중에는 같은 슬라이더의 추가 확정을 직렬화하되, 화면 표시와 오디오 미리보기는 마지막 사용자 값이 우선한다.
- 저장 실패 시 기존 메시지와 `설정 저장 다시 시도`를 표시하며, 메모리에 적용된 음량과 미리보기는 유지한다.
- 외부 진행 상태가 바뀌면 현재 조작 중이 아닐 때만 로컬 표시값을 동기화해 드래그 중 튐을 막는다.

`전체 소리`가 꺼져 있으면 두 슬라이더는 값을 보존하되 비활성화하고 미리듣기를 재생하지 않는다. 다시 켜면 저장된 두 음량으로 즉시 복귀한다. 음량 0은 해당 버스만 무음으로 만들며 전체 오디오 수명 주기를 중단하지 않는다.

## 9. 데이터 흐름

1. 저장소가 schema 5 진행 상태를 불러오거나 구버전을 기본 음량과 함께 이전한다.
2. `AppRoot`가 `soundEnabled`, `bgmVolume`, `sfxVolume`을 `AudioPort`에 동기화한다.
3. 설정 슬라이더 입력은 `MatchScreen`이 소유한 오디오 포트에 즉시 미리보기 값을 적용한다.
4. 조작 종료 시 `TowerController`가 마지막 설정을 메모리에 반영하고 저장 큐에 넣는다.
5. 갱신된 진행 snapshot이 다시 렌더링되며 `AppRoot`의 동기화 효과가 영구값을 확정한다.
6. 효과음 재생은 cue별 gain을 거쳐 사용자 SFX volume bus로 출력된다.

## 10. 오류 처리와 경합

- `setVolumes()`는 destroy 이후 아무 작업도 하지 않는다.
- `setVolumes()`는 유한한 입력을 `0~1`로 제한하고 `NaN` 또는 무한대 입력은 해당 버스의 마지막 정상값을 유지한다.
- gain 생성·연결·자동화 실패는 게임 동작에 예외를 전파하지 않는다.
- 음량 변경은 현재 재생 중인 BGM에 즉시 반영하되 트랙을 재시작하지 않는다.
- 음량 변경은 이미 시작된 매우 짧은 효과음을 재시작하지 않고 다음 cue부터 확실히 반영한다.
- suspend 중 변경한 값은 내부에 보존하고 resume 뒤 동일한 값으로 출력한다.
- 오래된 비동기 SFX decode는 기존 cue epoch 규칙을 계속 따라 음소거·suspend·destroy 이후 재생되지 않는다.
- 연속 저장의 성공·실패 순서는 기존 저장 큐가 소유하며 마지막 진행 snapshot을 재시도한다.

## 12. 완료 기준

- 기본 설정에서 여덟 효과음이 모바일 스피커로 식별 가능하다.
- BGM과 효과음 슬라이더가 서로의 버스에 영향을 주지 않는다.
- 전체 소리 토글과 0% 개별 음량의 의미가 구분된다.
- 사용자 BGM 음량이 크로스페이드나 덕킹 후에도 보존된다.
- 기존 schema 1~4 사용자는 진행·설정을 잃지 않고 70/100 기본 음량으로 이전된다.
- 설정이 재접속 후 유지되고 저장 실패 재시도가 마지막 값을 보존한다.
- 오디오 수명 주기, 게임 결정성, 모바일 입력과 AIT 패키지 검증이 회귀하지 않는다.
- 의존성 감사의 기존 미검토 항목은 이번 기능과 별도의 출시 차단 요소로 계속 명시한다.
