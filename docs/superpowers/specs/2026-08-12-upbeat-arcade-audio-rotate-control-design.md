# 밝은 아케이드 오디오와 퍼즐 회전 버튼 설계

작성일: 2026-08-12
상태: 사용자 승인 완료, 구현 계획 작성 전

## 1. 배경

현재 게임은 화면 경로에 따라 다섯 개의 BGM을 재생하고 여덟 개의 효과음을 지원한다. 그러나 저작 스크립트가 각 BGM을 단순한 사인파 베이스, 리드, 배음과 0.5초 단위 음계 반복으로 구성해 곡의 구간 변화와 리듬 정보가 부족하다. 60초 파일이더라도 체감상 짧은 패턴이 무한 반복되므로 침울하고 피로하게 들린다.

회전 효과음은 하나의 짧은 상승음으로 고정되어 있고 줄 제거 수, 콤보, 공격량을 반영하지 않는다. 회전 버튼은 파란 원형 CSS 버튼 안에 별도의 파란 사각 배경이 들어간 SVG를 다시 배치해 버튼 모양이 중첩되어 보인다.

## 2. 확정된 제품 결정

- 음악 방향은 밝은 아케이드 퍼즐 톤으로 한다.
- 보스전은 침울하게 만들지 않고 장난스럽고 긴장감 있는 악당 테마로 만든다.
- 각 BGM은 약 45~60초 동안 도입, A, B, 브레이크, 후렴으로 변주한 뒤 자연스럽게 반복한다.
- 구현 방식은 샘플 BGM과 반응형 효과음을 결합하는 하이브리드 방식으로 한다.
- 회전 버튼은 시안 B인 `통통 튀는 퍼즐 버튼`을 사용한다.
- 기존 게임의 멜로디, 음원, 캐릭터 음성, 고유 효과음을 복제하거나 샘플링하지 않는다. 밝고 익살스러운 아케이드 퍼즐이라는 추상적 분위기만 참고한다.

## 3. 목표

1. 반복 피로가 적고 화면 구간별 성격이 분명한 오리지널 BGM 다섯 곡을 제공한다.
2. 회전, 줄 제거, 콤보, 공격에 즉각 반응하는 효과음을 제공한다.
3. 강한 효과음이 BGM에 묻히지 않도록 짧은 음악 덕킹을 적용한다.
4. 회전 버튼의 중첩된 배경을 제거하고 기능을 한눈에 이해할 수 있게 만든다.
5. 현재의 음소거, 앱 백그라운드 정지, 3-2-1 복귀, 지연 없는 입력, 모바일 성능 특성을 유지한다.
6. 오디오 실패가 게임 규칙이나 입력 처리에 영향을 주지 않는 현재 경계를 유지한다.

## 4. 비목표

- 게임 상태에 따라 BGM 전체를 실시간 합성하는 음악 엔진
- 사용자가 곡을 선택하거나 외부 음원을 업로드하는 기능
- 음성 대사, 캐릭터 보이스, 온라인 스트리밍 오디오
- 게임 규칙, 점수 계산, AI 난이도 또는 리플레이 데이터 변경
- 기존 상용 게임의 멜로디, 음색 배열, 샘플 또는 식별 가능한 연출 복제

## 5. BGM 설계

현재 `MusicTrack` 다섯 개와 화면별 매핑은 유지한다. 따라서 화면 전환, 지연 로딩, 디코딩 캐시, 크로스페이드 구조를 새로 만들지 않는다.

| 트랙 | 사용 화면 | 방향 | 목표 속도 | 구성 |
| --- | --- | --- | --- | --- |
| `tower` | 타이틀, 이름, 캐릭터 선택, 랭킹, 타워, 층 소개 | 밝고 호기심 많은 출발 | 약 150 BPM | 32마디, 약 51초 |
| `early-floors` | 1~2층 대전과 결과 | 통통 튀는 주 멜로디 | 약 162 BPM | 32마디, 약 47초 |
| `late-floors` | 3~4층 대전과 결과 | 더 빠르고 긴장감 있는 축제 | 약 174 BPM | 36마디, 약 50초 |
| `demon-king` | 5층, 마왕, 부엉이 관련 대전과 결과 | 장난스럽고 과장된 악당 행진 | 약 168 BPM | 36마디, 약 51초 |
| `ending` | 엔딩 | 짧고 화려한 승리 축제 | 약 152 BPM | 32마디, 약 51초 |

각 곡은 다음 구간을 가진다.

1. 도입: 4마디 동안 리듬과 핵심 음색을 소개한다.
2. A: 8마디의 첫 주제를 제시한다.
3. B: 8마디 동안 화성, 리듬 또는 옥타브를 바꾼다.
4. 브레이크: 4마디 동안 악기 수를 줄여 귀를 쉬게 한다.
5. 후렴: 8~12마디 동안 주제와 대선율, 타악기를 결합한다.

음색은 펄스 또는 사각 리드, 삼각파 계열 베이스, 짧은 플럭, 노이즈 기반 킥·스네어·하이햇을 사용한다. 모든 음표, 리듬, 화성 진행은 프로젝트용으로 새로 작성한다. 시작과 끝의 박자·위상을 맞추고 BGM에는 전역 페이드아웃을 넣지 않아 반복 지점에서 인위적인 무음 구간이 생기지 않게 한다.

## 6. 오디오 자산 생성

`scripts/generate-authored-audio.cjs`를 결정적 스텝 시퀀서로 확장한다. 같은 소스와 버전에서 같은 PCM 및 MP3 결과가 생성되어야 한다.

- BGM 다섯 파일과 기존 효과음 여덟 파일의 경로는 유지한다.
- `@breezystack/lamejs@1.2.7`을 정확히 고정한 저작 전용 개발 의존성으로 사용한다.
- 저작 인코더는 런타임 번들 또는 AIT 패키지의 실행 코드에 포함하지 않는다.
- 인코더를 불러오지 못하면 무음 MP3를 생성하지 않고 명확한 오류로 종료한다.
- 생성된 MP3 파일은 저장소에 커밋해 앱 실행 중 생성 작업이나 네트워크 요청이 필요 없게 한다.
- 전체 BGM 용량은 현재 수준인 약 6 MiB를 크게 넘지 않게 하고 `check:assets`의 런타임 용량 제한을 유지한다.

## 7. 반응형 효과음 모델

`AudioPort.play()`는 기존 호출과 호환되는 선택적 재생 정보를 받는다.

```ts
export type CueIntensity = 0 | 1 | 2 | 3;

export interface SoundPlaybackOptions {
  readonly intensity?: CueIntensity;
  readonly duckMusic?: boolean;
}

play(cue: SoundCue, options?: SoundPlaybackOptions): void;
```

게임 코어의 `GameEvent` 형식은 변경하지 않는다. UI 경계에 순수 함수형 효과음 매퍼를 추가해 한 프레임의 이벤트와 공개 매치 뷰를 다음 규칙으로 변환한다.

- `lines-cleared`: `max(제거 줄 수 - 1, 콤보 - 1)`을 0~3으로 제한한다.
- `attack-sent`: `공격량 - 1`을 0~3으로 제한한다.
- 같은 프레임에 같은 cue가 여러 번 나오면 가장 높은 intensity만 한 번 재생한다.
- `piece-locked`, `garbage-landed`, 아이템, 승패 이벤트는 현재 cue 의미를 유지한다.
- 점수, 공격량, 보드 상태 또는 리플레이 결과에는 영향을 주지 않는다.

샘플 재생 시 intensity에 따라 재생 속도와 gain을 제한된 범위에서 바꾼다. 회전 cue는 별도 게임 상태 없이 오디오 포트 내부의 `0 → 1 → 2` 순환 변형을 사용한다. 변형 순서는 결정적이며 음소거 또는 오디오 오류가 입력 명령 전달을 막지 않는다.

효과음 성격은 다음과 같다.

- `move`: 짧고 부드러운 틱
- `rotate`: 방울처럼 튀는 2단 음, 세 높이를 순환
- `land`: 낮은 충격음과 가벼운 팝
- `clear`: 줄 수와 콤보에 따라 상승하는 벨·플럭
- `attack`: 공격량에 따라 굵어지는 휙 소리와 충격음
- `item`: 반짝이는 짧은 아르페지오
- `win`: 빠르고 명확한 승리 팡파르
- `loss`: 침울하게 길어지지 않는 짧은 하강음

## 8. BGM 덕킹

강한 줄 제거 또는 공격이 발생하면 현재 음악 gain을 약 90ms 동안 기준의 약 65%까지 낮추고 약 180ms 동안 복원한다. 연속 요청은 가장 최근 요청을 기준으로 합쳐져 오래된 복원 예약이 새 덕킹을 취소하지 않아야 한다.

다음 경우에는 덕킹을 예약하지 않거나 남은 예약을 안전하게 무효화한다.

- 사운드가 꺼져 있음
- 오디오 컨텍스트가 suspend 또는 destroy 상태임
- 활성 BGM이 없음
- 새 트랙으로 교체되는 중임

덕킹 실패는 예외를 UI로 전파하지 않는다.

## 9. 회전 버튼 설계

현재 원형 CSS 버튼 안에 배경 사각형을 포함한 SVG가 들어가는 이중 구조를 제거한다.

- 버튼 외형은 약 76px 원형이며 360px 화면에서도 최소 56px 터치 영역을 보장한다.
- 바깥쪽은 밝은 청록 테두리, 안쪽은 분홍 계열의 통통 튀는 아케이드 버튼으로 구성한다.
- 아이콘은 서로 다른 색의 두 블록과 회전 궤도만 포함하고 자체 배경 사각형을 갖지 않는다.
- 눌리는 동안 버튼은 아래로 약 2px 이동하고 아이콘은 짧게 회전한다.
- 애니메이션은 `transform`만 사용하며 입력 dispatch를 지연시키지 않는다.
- 빠른 연속 탭, 포인터, 키보드 Enter·Space 처리와 한국어 접근성 이름 `시계 방향 회전`을 유지한다.
- `prefers-reduced-motion`에서는 아이콘 회전을 제거하고 눌림 위치 변화만 최소화한다.

기존 자산 경로 `public/assets/ui/rotate.svg`는 유지하되 SVG 내부를 투명한 두 블록·궤도 아이콘으로 교체한다. 따라서 자산 manifest 스키마는 바뀌지 않는다.

## 10. 구성 요소와 데이터 흐름

1. 게임 코어가 기존과 동일하게 `GameEvent[]`와 `PublicMatchView`를 제공한다.
2. 새 순수 매퍼가 이벤트를 cue별 최대 intensity와 덕킹 여부로 집계한다.
3. `MatchScreen`은 집계 결과를 `AudioPort.play()`에 전달한다.
4. `createWebAudioPort`는 샘플 버퍼를 재사용하고 intensity 및 회전 순환에 맞춰 source playback rate와 gain을 설정한다.
5. 강한 cue는 기존 music gain 노드에 짧은 덕킹을 예약한다.
6. 샘플 로딩 또는 디코딩이 실패하면 같은 intensity 계층을 반영한 밝은 다중 오실레이터 대체음을 사용한다.

오디오 처리는 게임 코어, AI, 점수, 저장소 계층과 분리한다.

## 11. 오류 처리와 수명 주기

- 모든 `play()` 호출은 동기 입력 흐름을 소유하지 않으며 내부 실패를 비치명적으로 처리한다.
- 이미 디코딩한 버퍼 캐시는 유지하고 현재 BGM만 루프한다.
- 앱 백그라운드 진입 시 기존처럼 suspend하고 복귀 카운트다운 시작 전에 resume한다.
- 음소거 시 활성 cue와 덕킹 예약을 정리하고 재활성화 시 오래된 cue를 재생하지 않는다.
- destroy 이후 완료된 비동기 디코딩은 새 source 또는 gain 변경을 만들지 않는다.
- 런타임에서 외부 오디오 서비스나 네트워크 스트리밍에 의존하지 않는다.

## 12. 성능 예산

- 기존과 동일하게 BGM 다섯 개를 필요할 때 지연 디코딩한다.
- 실시간 음악 시퀀서나 프레임 단위 오디오 계산을 추가하지 않는다.
- 한 프레임에서 같은 cue는 한 번만 재생한다.
- 효과음 변화는 짧은 source, gain, playback rate 설정으로 제한한다.
- 회전 버튼 애니메이션은 레이아웃을 다시 계산하지 않는 transform 기반으로 구현한다.
- `ASSETS_OK` 런타임 용량 한도와 AIT 패키지 검증을 계속 통과해야 한다.

## 13. 테스트와 검수

### 자동 검증

- 이벤트 매퍼의 줄 수, 콤보, 공격량, 최대 intensity 집계 테스트
- 같은 프레임 cue 중복 제거 테스트
- 회전 cue의 3단 순환과 intensity별 playback rate·gain 테스트
- 덕킹 예약, 연속 덕킹, 음소거, suspend, track 교체, destroy 테스트
- 샘플 로딩 실패 시 대체음 테스트
- 회전 버튼의 포인터·키보드 단일 dispatch, 접근성 이름, 아이콘 구조 테스트
- `npm run typecheck`
- `npm test`
- Python 저작 자산 테스트 직접 실행
- `npm run test:e2e`
- `npm run test:delivery-gates`
- `npm run check:assets`
- `npm run check:source-policy`
- `npm run build:web`
- `npm run build:ait`
- `node scripts/verify-ait-package.mjs artifacts/ait/game.ait`

### 수동 검수

- 브라우저에 다섯 BGM과 주요 효과음 재생 목록을 제공해 분위기와 반복 지점을 확인한다.
- 360×640 및 430×932 화면에서 회전 버튼이 보드 공간을 침범하지 않는지 확인한다.
- 빠른 연속 회전, 콤보, 큰 공격에서 효과음이 겹쳐 불쾌한 클리핑을 만들지 않는지 확인한다.
- 음소거, 백그라운드 복귀, 3-2-1 카운트다운 후 음악이 중복 재생되지 않는지 확인한다.

## 14. 완료 기준

- 다섯 BGM이 서로 다른 해시와 서로 구별되는 구성·리듬을 가진다.
- 각 BGM이 승인된 밝은 방향과 45~60초 다구간 구조를 따른다.
- 회전 효과가 세 높이로 순환하고 줄 제거·공격 효과가 intensity에 반응한다.
- 강한 cue에서만 짧은 덕킹이 발생하고 음악이 정상 음량으로 복원된다.
- 회전 버튼이 시안 B의 두 블록·회전 궤도 형태이며 중첩 사각 배경이 없다.
- 모바일 입력, 접근성, 오디오 수명 주기, 게임 결정성이 회귀하지 않는다.
- 기능 테스트와 빌드·AIT 검증이 통과한다.
- 기존 의존성 감사의 미검토 항목은 이 기능과 별도 출시 차단 요소로 계속 명시한다.
